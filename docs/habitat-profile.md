# Habitat Profile Feature Proposal

This document outlines the design and data architecture for the "Habitat Profile" feature, which allows users to provide specific environmental context for their audio recordings to improve AI identification accuracy.

## Revised User Flow

The Habitat Profile is an optional step integrated directly into the recording workflow. It is designed to be contextual to each specific recording event.

1.  **Record Audio:** The user captures an audio recording as normal on the "Record" page.
2.  **Habitat Profile Screen (Optional):** After stopping the recording, the user is presented with a new, optional "Habitat Profile" screen. This screen contains:
    *   **Photo Upload:** A button to "Add Habitat Photo," allowing the user to upload an image from their device's camera or library.
    *   **Text Description:** A text area prompting the user to describe the immediate environment (e.g., "dense gum tree forest near a creek," "rocky coastal cliff with low shrubs").
3.  **Initiate Analysis:** The user can add a photo, a description, both, or neither. They then press a "Start Analysis" button.
4.  **Send to AI:** All available data—the audio, location, timestamp, and any new habitat information—is sent to the AI for analysis.

## Data Storage & Architecture

To maintain our flat, searchable data model, all new habitat information will be added as optional fields to the existing `all_analysis_runs` collection documents in Firestore.

### New Fields in `all_analysis_runs`

A document in this collection will be updated to include:

-   `habitatPhotoUrl` (string, optional): A path to the user-uploaded habitat photo in Firebase Storage.
-   `habitatDescription` (string, optional): The user's raw text description of the habitat.
-   `aiGeneratedHabitatTags` (array of strings, optional): Structured tags generated by the AI based on its analysis of all available habitat data (photo, text, location, etc.). This provides a queryable field for future analytics.

### Firebase Storage Structure

To securely store the user-uploaded photos, a new top-level folder will be created in Firebase Storage:

-   `users/{userId}/recordings/`: For audio files (existing).
-   `users/{userId}/habitats/`: For habitat photos (new).
-   `users/{userId}/bird-photos/`: For user-specific bird photos linked to a log entry (new).

This structure allows us to use Firebase Storage Security Rules to ensure users can only access and upload media associated with their own user ID, maintaining data privacy.

This approach integrates the new feature seamlessly into our existing architecture, enhancing data richness without compromising our commitment to a scalable and secure design.
